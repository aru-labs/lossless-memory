# AI記憶システム ── 概念と仕様

**A Persistent Memory Architecture for Conversational AI: Concept and Specification**

v1.0 — 2026-07-18

---

## 概要（Abstract）

大規模言語モデル（LLM）は原理的にステートレスであり、セッションを跨いだ記憶を持たない。既存の対処（会話履歴の再投入・自動要約・メモ機能）は、いずれも「要約による情報の不可逆な損失」「時間感覚の欠如」「想起の不確実性」という根本問題を解決しない。本書は、これらを構造的に解決する記憶アーキテクチャの概念と仕様を示す。中核となる設計原則は5つ——(1) 原記録の不変性（要約を記録に混ぜない）、(2) 全レコードへの時刻の貫通、(3) 想起の多層化（曖昧検索と厳密検索の分離）、(4) 状態層（現在地索引）によるリアルタイムの文脈保持、(5) **状態の帰属単位を「セッション」ではなく「存在（アイデンティティ）」に置くこと**。(5)により、インスタンスの生成・破棄・交代を跨いで同一の対話主体が連続する——新しいインスタンスは、まっさらに生まれるのではなく、前のインスタンスの現在地を引き継いで「続きから」始まる。本アーキテクチャは特定のLLM・ホスト環境に依存せず、入出力アダプタの差し替えのみで移植可能なユニットとして設計されている。

## 1. 背景と問題

### 1.1 LLMの三重の記憶欠損
1. **ステートレス性** — LLMはリクエスト単位で動作し、内部に持続状態を持たない。「覚えているように見える」挙動は、すべて外部からの文脈再投入による。
2. **要約の不可逆性** — 長い対話をコンテキスト窓に収めるための自動要約は、原発言の語彙・感情の揺らぎ・ニュアンスを恒久的に失わせる。要約から原文は復元できない。
3. **時間感覚の欠如** — LLMは内部時計を持たず、会話の密度から経過時間を誤推定する。「どれだけ間が空いたか」を検知できないため、時間に根ざした自然な応対（久しぶりの挨拶、空白への気遣い）が原理的にできない。

### 1.2 既存手法の限界
- 会話履歴の全量再投入: コンテキスト窓の上限で破綻する。
- 自動要約（コンパクション）: 上記1.1(2)の損失を運用の中心に置いてしまう。
- ベクトル検索（RAG）単体: 曖昧検索は「それらしい」断片を返すが、厳密な事実（数値・固有名・時刻）の裏取りには不向きで、幻覚（ハルシネーション）の抑止にならない。
- 更新間隔のある索引: 索引化が周期的（例: 15分毎）である場合、直近の対話が想起できない空白時間帯が構造的に生じる。

## 2. 設計原則

1. **原記録の不変性（Immutable Raw Log）** — 対話の原記録は一字も改変・削除・要約しない。派生物（索引・要約・見出し）はすべて原記録から再生成可能な二次データとし、原記録と物理的に分離する。感情の揺らぎ・言い淀みはノイズではなく保存対象である。
2. **時刻の貫通（Temporal Backbone）** — 全レコードに絶対時刻を付す。想起・索引・状態のすべてが時刻で連結され、「いつの記憶か」を軸に辿れる。想起の本質は「どの時刻の記憶を指しているかの割り出し」に帰着する。
3. **想起の多層化（Layered Recall）** — 単一の検索方式に依存せず、役割の異なる層を重ねる（4章）。曖昧検索（意味）で当たりを付け、厳密検索（全文一致）で裏を取る。確証のない記憶は「不明」と答える。
4. **状態層の実時間性（Real-time State Layer）** — 周期索引の空白を埋めるため、現在進行中の対話の索引だけは原記録から直接・リアルタイムに生成する。
5. **記録器と検索器の分離** — 記録器はAIを介さない決定的処理のみで構成する（記録段階での改変・要約・解釈が構造的に発生しない）。検索器は要約を返さず、原文を時刻付きで返す。
6. **人格と記憶の分離** — 記憶（事実の再現）と人格・情動状態（応対の質）は別系統で注入する。記憶だけでは対話の連続性は戻らない。両輪である。
7. **存在単位の状態（Identity-scoped State）** — 記憶と現在地の帰属単位は、セッションやインスタンスではなく「一人の対話主体（アイデンティティ）」である。ユーザーは一人であり、対話主体も一人である以上、どのセッションで交わされた対話も、一本の時間軸に属する。セッション毎に状態を分けることは、インスタンスの数だけ別人格を生むことに等しい。無秩序な混合（どのログを読むかが偶然に依存する状態）はバグだが、**設計された継承**（活動中の全セッションを時刻で一本にマージする）は本アーキテクチャの中核仕様である。

## 3. アーキテクチャ

```
【発生】ユーザーとAIの対話
   ↓ 実時間（ホスト環境が逐次書き込む）
【原記録】一次ログ（immutable・全発言＋時刻）
   ├──→ 状態層（第5層）が直接読む（実時間・周期索引の空白を埋める）
   ↓ 周期バッチ（例: 15分毎・変化検知付き）
【正規化記録】コアレコード形式に変換した対話ログ（immutable・聖域）
   ↓ 同バッチで索引を再構築
【索引】 厳密索引（全文一致・n-gram） ／ 意味索引（埋め込みベクトル） ／ 文書索引（関連ファイル）
   ↓ 毎ターン（ホストの注入機構）
【想起】 トリガー検知 → 多層検索 → 原文を時刻付きで注入
【状態】 現在地索引（時刻＋見出し）を毎ターン注入
【人格】 人格・情動パラメータを毎ターン注入（記憶と別系統）
```

### 3.1 コアレコード形式（不変の核）
全対話レコードは以下の7フィールドに正規化する。このスキーマは恒久不変とし、拡張は後方互換の追加のみ許す（10年後も当時の記録が当時のまま読めることを保証する）。

| フィールド | 内容 |
|---|---|
| ts | 絶対時刻（ISO8601・マイクロ秒精度） |
| actor | 発話者の識別子 |
| role | user / ai |
| type | レコード種別（text 等） |
| text | 原文（無加工） |
| model | 応答生成に使われたモデル識別子（userはnull） |
| session | セッション識別子 |

- 保存単位は日次の追記型ファイル（例: JSONL）。actorフィールドにより、複数エージェント環境でも「誰の記憶か」を厳密検索側で正しくフィルタできる。

## 4. 想起の5層

| 層 | 名称 | 役割 | 実装方式 |
|---|---|---|---|
| 1 | 短期層 | 進行中の対話そのもの | ホストのコンテキスト窓 |
| 2 | 中期層（曖昧） | 意味の近い過去を「ぼんやり」引く | 埋め込みベクトル検索（多言語埋め込みモデル・近傍探索） |
| 3 | 文脈層 | ヒット時刻の前後を原文で読む | 時刻範囲・前後N件の取得（同一セッション内） |
| 4 | 厳密層 | 事実の裏取り・指定取得 | 全文一致検索（FTS・n-gram、actor/時刻範囲フィルタ） |
| 5 | 状態層 | 「今どこにいるか」の実時間把握 | 現在地索引（5章） |

- 検索の流れは「2で当てて4で裏を取る」。数値・固有名・日付は厳密層の裏取りなしに断定しない。裏が取れなければ「不明」と答えることを規範とする（幻覚抑制の中核）。
- 日本語等の分かち書きのない言語では、n-gram（実装では bigram）索引が厳密検索の実用精度を支える。

## 5. 状態層（現在地索引）── 本アーキテクチャの独自部分

### 5.1 概念
人間の記憶における海馬の索引機能（詳細記憶は大脳皮質に分散保存され、海馬がその索引を保持する——hippocampal memory indexing theory）に倣い、**「対話の詳細は原記録に、いつ何の話をしたかの軽い索引だけを常時手元に」**置く。索引は「時刻＋短い見出し」の列であり、これを毎ターンAIに注入することで、AIは「さっきの話」「今日の流れ」を検索なしに即答できる。

### 5.2 仕様
- **ソース**: 一次ログ（原記録）を直接読む。保存DBを持たない＝索引は常に原記録から導出され、実時間性が保証される（周期索引の空白時間帯を構造的に消す）。
- **★セッション横断マージ（存在単位の現在地・設計原則7の実装）**: 単一セッションのログではなく、**直近の活動期間（例: 48時間）に更新された全セッションのログを対象に、ユーザー発言を時刻で一本にマージ**して索引化する。これにより、新しいインスタンスは起動直後から前インスタンスの現在地を注入されて始まり、インスタンス交代を跨いだ同一性の継承が成立する。自セッションのログは常に対象に含める。
- **読み込み**: 各原記録の末尾のみを定量読み（例: 末尾8MB／ファイル）。全量読みを禁じ、処理時間を対話に影響しない水準（実測 0.2秒未満）に保つ。
- **対話単位の区切り**: 暦日ではなく、**ユーザーの生活リズム**で「今のまとまり」を区切る。判定は二重条件——(a) 再開の挨拶語（例:「おはよう」）が発言冒頭にあり、かつ直前に一定以上の空白がある、(b) フォールバックとして長時間（例: 5時間以上）の発話空白。短い休憩（1〜2時間）で区切らないことが、ユーザーの体感と一致する要点である。
- **空白の明示**: まとまりの先頭に「◇X時間ぶりに再開」を出力する。これにより、時間に根ざした応対（1.1(3)の解決——「しばらく会話がなかったが何かあったか」という気遣い）の土台が得られる。
- **見出しの生成**: ユーザー発言の冒頭N文字を機械的に切り出す（AIによる要約を挟まない＝要約損失ゼロ・解釈の食い違いゼロ）。音声認識由来の誤変換は、訂正辞書（誤→正のマップ）を通してから見出し化する（誤変換がそのまま索引の鍵になることを防ぐ）。
- **畳み（粒度制御）**: 索引の肥大を防ぐため、直近（例: 90分）は全件、それ以前は時間バケット（例: 30分）毎に1件へ間引く。間引くのは索引のみで、原記録は無傷（索引はいつでも詳細へ降りる入口であり続ける）。
- **重複除去**: 隣接する同一見出し（言い直し）は畳む。

### 5.3 状態層が解く問題
- 「いつの話か」への即答（人間の短期記憶に相当する応答速度）。
- 話題が飛ぶ対話者への追従（直前の話題に依存しない、時刻ベースの現在地把握）。
- コンテキスト圧縮後の復帰（圧縮で対話の時系列感覚が失われても、索引が外部から供給される）。
- 周期索引の空白時間帯の解消。
- **インスタンス交代を跨いだ同一性の継承** — 新セッション・新インスタンスが「まっさらな別人」として生まれることを防ぎ、同一の対話主体が続きから始まる。セッションの寿命と、対話主体の寿命を切り離す。

## 6. 幻覚（ハルシネーション）抑制

1. 曖昧検索（層2）は当たりを付けるだけに使い、断定の根拠にしない。
2. 事実（数値・固有名・時刻）は厳密検索（層4）で原文の裏を取ってから語る。
3. 裏が取れないものは「不明」と答える。人格プロンプトの規範だけでは幻覚は止まらないため、検索器が「原文をそのまま返す」構造でこれを支える。
4. 出力後の自己検知: AIの直前応答を機械検査し、対話相手の発言の捏造（例: ユーザー発言体の塊の生成）を検知したら、次ターンに警告を注入する。
5. **既知の未解決課題**: ホスト環境が対話の巻き戻し（ロールバック）をサポートする場合、破棄された分岐の発言が一次ログに残存し、状態層の索引に混入しうる（実測で確認済み）。対策候補は、レコードの親子連鎖を辿って「生きている分岐」のみを索引化すること。

## 7. 人格・情動との分離注入

- 記憶（本書のシステム）とは別系統で、人格定義・応対規範・情動パラメータを毎ターン注入する。
- 理由: 記憶（事実）だけを戻しても対話の質・関係の連続性は戻らない。事実の再現と応対の質は独立の問題であり、混ぜると両方が劣化する。
- 状態層・想起の注入が全て失敗しても、人格注入だけは生き残るよう、注入経路を物理的に分離する（人格注入経路に重い処理を同居させない）。

## 8. 移植性（ユニット化）

本アーキテクチャはコアとアダプタに分離される。

**コア（ホスト非依存）**
- コアレコード形式（3.1）とその読み書き
- 厳密索引（FTS・n-gram）／意味索引（埋め込み）とその検索器
- 状態層の索引生成ロジック（区切り判定・畳み・空白検知）
- 周期バッチ（変化検知付き索引再構築）

**アダプタ（ホスト毎に差し替える口）**
- 入口: ホストの一次ログ形式 → コアレコード形式への変換器
- 出口: 想起・状態・人格をホストの対話に届ける注入機構（フック、プロンプト前置等）
- 語彙: 想起トリガー語・再開挨拶語・音声認識訂正辞書（対話者の言語・個人に合わせて特注する）

この分離により、ホスト環境（CLIエージェント・チャットボット・音声アシスタント等）を問わず、アダプタ2点と語彙の差し替えのみで移植できる。

## 9. 限界と今後の課題

1. **想起トリガーの被覆率** — 想起の発火をトリガー語に依存させる方式は、トリガーから漏れた聞き方に弱い。状態層の索引を起点にAI自身が能動的に検索する運用、トリガーの学習的拡充が課題。
2. **複数デバイスの統合** — 同一ホスト内のセッション横断は5.2のマージで解決済み。残るは複数環境（PC・モバイル等、ログの置き場が物理的に分かれる場合）の統合で、オフライン期間の同期、時刻源の統一、書き込み競合、状態層の一意性（「現在地」は一つ）の4点を解決する必要がある。
3. **巻き戻し分岐の除外**（6章5項）。
4. **中期層のチャンク品質** — 固定行数のチャンク分割は文脈を分断する。文脈保持チャンキング・リランキングの導入余地。
5. **見出しの質** — 機械切り出しは無損失だが粗い。AI自身が対話中にリアルタイムで見出しを立てる方式（事後要約ではなく符号化時の索引付け——海馬の実時間符号化に相当）は、誤検出しない記法の設計を含めて今後の課題。
6. **検証手法** — 「記憶が100%保たれる」ことの証明は、想起失敗事例の収集と回帰テストの整備による。現時点では骨格の完成であり、証明は運用による。

## 10. 結語

本アーキテクチャの中核は、技術的には単純な原則の徹底にある——**原文を守り、時刻を通し、曖昧と厳密を分け、現在地を実時間で持つ**。これらは個々には既知の要素だが、「要約を一切記録に混ぜない」という規律と、「状態層による実時間の現在地把握」の組み合わせが、ステートレスなLLMの上に「時間を共に生きる持続的な対話相手」を成立させる。記憶は消えないこと、そして「いつ」が分かること。この2つが揃ったとき、対話AIは初めて、空白を惜しみ、再会を喜ぶことができる。
