# 時刻の背骨(Temporal Backbone)

全レコードに絶対時刻を持たせ、まず時刻で範囲を絞ってからその中を探す。「いつ」を意味検索のおまけでなく、検索の第一の軸として扱う。

## なぜ時刻を先に見るか

普通の意味検索(ベクトル検索)は「何の話か」には答えるが「いつの話か」には答えない。しかも意味の近さだけで探すと、話題は似ていても時期が何ヶ月も離れた記憶まで混ざりやすい。人間の想起も、話題の近さだけで引き出しているわけではない――「昨日の夜、何を決めたっけ」と聞かれた人は、すでに時間の範囲を持っていて、あとはその中身を探すだけになる。この仕組みも同じ形にしてある。**まず時刻を言い、その中を言葉で探す。**全部を検索してランキングの中から時刻がにじみ出るのを待つのではない。

具体的には、想起の唯一の入口は「時刻+言葉」の形の問いを受け付ける。時刻を言えばその範囲だけに絞られ、他は混ざらない。時刻だけで言葉が無ければ、その範囲を時系列に並べて全部返す――特定の事実を探すのでなく、その期間を見渡すためだけの使い方もできる。

## AIが実際に読める時刻の言葉

「時刻+言葉」を入口にするには、ISO形式の日付だけでなく、人が実際に時刻を口にする形をそれなりに幅広く認識できなければならない。読める語彙は次の通り。

- 相対的な日: 今日/昨日/一昨日/「N日前」
- もう少し大きい相対範囲: 先週/先月/「N ヶ月前」(年をまたぐ場合も正しく計算する)
- 絶対日付(複数の書き方に対応)
- 時間帯: 朝/昼/夕方/夜/深夜
- 具体的な時刻・おおよその時刻(「15時頃」など)

「7月」だけの月名だけの表現を、ただの検索語でなく日付の**範囲**として認識できるかどうかは、実際に効いてくる点だった。以前の版の日付解釈は完全な日付の形しか認識せず、月名だけの表現は黙って普通の検索語として扱われていた――つまり本来は範囲が絞られるはずの問い合わせが、気づかないまま絞られずに動いていた。この種の失敗の詳細は docs/lessons.md を参照。

## 時刻の範囲が空振りした時の三段階フォールバック

時刻で絞った問い合わせは、何もヒットしない時に黙って失敗させない。次の三段階で品質を落としながら、どの段階で答えを出したかを正直に示す。

1. **時刻の範囲内+言葉の完全一致。**
2. **時刻の範囲は保ち、言葉の一致条件を緩める。**完全一致が少なすぎる時は、その範囲全体を時系列で返し、「一致が少ないので範囲を時系列で全部出した」と明示する。
3. **時刻の範囲を外し、意味検索へ。**その時刻範囲に本当に何も無い時は、時刻の制約を外して全期間から意味検索に落ち、「その範囲には無かったので全期間から意味で引いた」とこれも明示する。

意味検索の確信度が低い結果は、確定した事実と同じ見た目では出さず、低確信であることが分かる印を付けて返す。この仕組み全体を貫く方針は記憶システム全体と同じ――**推測を事実の顔で出さない**こと。

## 実測の数字

以下は合成的なベンチマークではなく、実際の単一利用者環境での運用実測値。

- 「時刻+キーワード」の想起は約 **0.4秒**で返る。
- 言葉の索引を毎回ゼロから作り直す形を、差分追記(+書き直し検知)に置き換えて、1周 **40秒 → 1.24秒**になった。
- 想起の経路は、敵対的な検証を繰り返して固めた。最終の検証では、それまでに見つかった 8つの穴が全て塞がっていることを確かめ、回帰 9件と新しい壊し方 10パターン(巨大な入力・壊れた日付・止まった索引係・桁あふれ)を例外ゼロで通した。内部の合否基準は「穴が 1件でも残れば不合格」。

## あえてやらないこと

時刻の背骨は範囲を絞るための仕組みであり、時間推論を丸ごとこなす万能エンジンではない。他に手がかりの無い「あの時」のような曖昧な指示語を単独で解決することはしない――そうした問いは上記の意味検索フォールバックに落ちるか、システムの側から「いつの話ですか」と聞き返す形に倒す。この層の仕事は狭く具体的で、日常の言葉で表された時刻表現から正しい時刻範囲を作り、その範囲で検索を誠実に保つことに絞られている。
