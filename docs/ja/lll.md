# LLL ── Left Leg Layer(左足の一歩レイヤー)

LLL(Left Leg Layer・左足の一歩レイヤー)は「今どの話題にいるか」を毎ターン注入する軽量な現在地の索引。話が飛ぶ相手にも検索なしで追従できるようにするための仕組みで、人間が索引の中の項目に優先度を付け、AIは読むだけ。

## なぜ「左足」か

この名前は技術用語の略称ではなく、内部の比喩から来ている。右足=統計的な予測(次に何の話になるかを先読みしようとすること)、左足=今どこに立っているかを一瞬ごとに正確に知り、そこから一歩ずつ、たとえ飛び飛びであっても付いていくこと。この層は後者の考え方の実装であり、次の話題を予測しようとはせず、今の話題の索引を安く正確に保つことに徹する。

概念としては海馬インデックス理論(hippocampal memory indexing)を下敷きにしている。詳細な記憶(生の会話そのもの)はどこか別の場所に置かれ、「いつ何の話をしたか」だけの、ずっと軽い索引が時刻で紐付けられて隣に置かれる。LLLは、今進行中の会話についてのその索引にあたる。

## 索引の作り方

- **専用のデータベースを持たない。**索引は必要になるたびに、生きた会話のトランスクリプトから直接その場で計算する。同期させておくべき何かが別に存在するわけではなく、ズレて古くなることもない。
- **末尾だけを読む。**各トランスクリプトは末尾の一定量だけを読み、全量は読まない。これにより、毎ターン走らせても気づかれない速さ(1秒未満)を保っている。
- **セッションをまたいで統合する。**この会話の主体は一つのセッションに閉じたものではなく連続しているため、索引は単一セッションのログではなく、直近の一定期間に活動のあった全セッションのログを時刻で一本にマージして作る。これにより、新しく始まったセッションでも、真っさらな状態でなく現在の話題を引き継いで始められる。
- **話の実際のリズムでまとまりを区切る。**発話の間に数分の空白ができた時、または一つの話が一定時間以上続いた時に、新しい「まとまり」を始める――固定のスケジュールでは区切らない。
- **要約ではなく見出しの抜き出し。**各まとまりの見出しは、実際の発言の中で最も具体的な語(固有の名詞や特定の用語)が密な節を機械的に選んで作る。モデルによる生成や言い換えは行わない。言葉は一切変えず、選ぶだけ。これは意図的な選択で、索引が要約をしてしまうと、この記憶システム全体が避けようとしている情報の損失をまさに索引の側で再導入してしまう。発言冒頭以外の節を使った場合はその印を付け、原文そのままの冒頭と取り違えられないようにする。
- **長さを抑えるための畳み。**直近の活動(たとえば直近1時間)は各まとまりごとに全件そのまま保持し、それより古いものは固定の時間バケット(たとえば30分ごと)につき最大1件へ間引く。これにより長いセッションでも索引が際限なく肥大しない。畳みは索引だけに効き、元の生ログからは何も消えず、いつでも全文を読み返せる。
- **注入する範囲には上限を設ける。**実際に毎ターンモデルへ注入されるのは索引全体ではなく、直近の一定範囲(数時間程度)に限られる――それより深い過去は、この層ではなく検索ベースの想起層の仕事になる。収まりきらずに切った場合は、黙って落とすのではなく「これより前にN件・省略」と一行で明示する。
- **特に熱量のある瞬間には印を付ける。**小さくルールベースのキーワード判定で、はっきりした決定・約束・強い訂正と読める発言を検知し、それらは常に独立した1行として浮かび上がらせる――畳みの対象になる位置にあっても埋もれさせない。

## 優先度は人間だけの領域

自動で作られる話題索引とは別に、各項目には優先度の印を付けられる。ここはLLLの中で、明確に「AIが触ってはいけない」部分。

- 優先度の段階はいくつかに分かれ、一番上は生存・安全に直結する最重要事項だけの特等席、その下に通常の重要度がいくつか、一番下は「保留・急がないが忘れない」という段階がある。これとは別に、AIに特に注意を向けさせるための単発の「合図」印と、「完了」印もある。
- **これらの印は人間だけが付け・変え・外す。**AIの役目は、それを読んで人間が今何を大事にしているかを頭に入れておくことであり、優先順位を勝手に整理したり、自分の判断で完了とみなしたり、期限を過ぎたように見えても印を外したりはしない。逆に、印が付いていない項目は人間の今の関心の外にあるとみなしてよく、完了扱いにしてかまわない。
- 毎ターンの注入量を抑えるため、最上位の少数の特等席だけは件数制限なしで注入し、それ以外の段階は直近の数件までに制限する。人間側が見る画面には同じ制限は無く全件が見える――AIが毎ターン受け取るのは、より大きな蓄積へのあえて狭められた窓であり、注入が来なかったからといって「もう全部見た」と思い込んではいけない。

## 誰が話題項目を書き込むか

新しい話題項目は、話が変わるたびに自動で追記されるわけではない。索引はあくまで人間が実際に追いたいと思っているものを映すべきであり、自動追記の方針は低シグナルな項目で索引を埋め尽くし、本当に大事な項目を埋もれさせがちになる。そのため、

- AIは明示的に指示された時だけ項目を追記する。
- 人間は自分の側のインターフェースから直接、同じ記録に項目を追記できる。
- 特定の語を含む項目に「完了」の印を付けることはできるが、元の項目の文言そのものは変更しない――履歴を削除・書き換えるのではなく、その上に完了の印を別建てで重ねるだけ。

## LLLではないもの

これはタスクリストでも、期限を管理する場所でもない――優先度の印は、片付けていくべき作業の待ち行列ではなく、人間が今視界に入れておきたいと思っていることの反映に過ぎない。また、これは過去の唯一の記憶でもない――これは*直近*の文脈だけを対象にした、短く安価で常時稼働の索引であり、計算量とモデルの注意の両方を小さく保つために意図的に範囲を絞ってある。それより古いもの、あるいは今の索引がたまたま拾わなかったものは、docs/memory-system.md に記した検索ベースの想起層の仕事になる。
